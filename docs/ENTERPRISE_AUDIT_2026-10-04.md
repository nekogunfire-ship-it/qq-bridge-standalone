# 企业级质量审查报告（2026-10-04）

## 结论

项目核心离线回归通过，具备 Direct Runtime、DSH 可选集成、桌面端管理、安全边界和脱敏打包能力。本轮补齐持续集成、依赖更新自动化、安全披露政策与贡献门禁，并清理文档审计问题和已知传递依赖告警。

## 审查范围

- 架构与配置：DSH 解耦、运行时切换、配置可移植性、默认权限。
- 安全与隐私：白名单、SSRF、日志与打包脱敏、依赖漏洞。
- 可靠性：核心审计、桌面端、Direct Runtime、MCP、图片输入、ComfyUI 管理。
- 交付：锁文件、可重复安装、文档完整性、Windows CI、依赖更新策略。

## 已完成改进

1. 新增 Windows GitHub Actions 质量门禁，使用锁文件安装并设置最小仓库权限、超时和并发取消。
2. 新增 Dependabot，对 npm 依赖和 GitHub Actions 做周期性更新检查。
3. 固定存在安全公告的传递依赖到已修复版本，防止上游宽松依赖重新解析到旧版本。
4. 新增 `SECURITY.md` 与 `CONTRIBUTING.md`，统一漏洞报告、安全基线和合入标准。
5. 修复失效的 `HANDOFF.md` 链接，将视频素材纳入文档索引，并把运行时 prompt 正确标记为非说明文档。
6. 新增单一 `npm run quality:ci` 命令，使本机与 CI 使用同一套门禁。

## 验证证据

以下命令必须全部成功：

```powershell
npm run quality:ci
npm audit --omit=dev
```

质量门禁不连接真实 QQ、DSH、SnowLuma 或付费模型端点；图片链路在无服务时会跳过在线探测，但仍验证配置、附件传递和本机地址防护。

## 剩余风险与建议

- Windows 安装程序尚未做商业代码签名；对公网大规模分发前建议配置可信代码签名证书。
- 仓库未声明独立 LICENSE，且包含上游衍生基础；公开再分发前应确认上游许可证兼容性并补齐法律文本。
- 可选 DSH 客户端包声明了一组只在完整 DSH 主程序内提供的 peer dependencies，因此单独执行 `npm ls --all` 会报告这些可选 peer 缺失；Direct Runtime 与现有桥接测试不受影响，后续应优先以稳定的独立 DSH 客户端替换该 RC 包。
- CI 无法覆盖真实 QQ 登录、第三方 API 波动、GPU 驱动和大模型下载；每次 Release 仍需在隔离测试账号上完成冒烟测试。
- 本地控制台虽默认仅监听回环地址，仍应保护 Windows 用户会话和配置目录，不应通过公网反向代理直接暴露。
